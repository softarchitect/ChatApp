23. Conversation Activity Logs (System Events Inside Chat)

Requirement

All important conversation updates must be displayed inside the chat screen as system messages (timeline events).

These must appear as non-editable, system-generated entries inside the conversation thread.

Examples of events that must be shown:
• Ahmed added a tag.
• A tag was removed by Ahmed.
• Sultan assigned the conversation to you.
• The manager removed the assignment.
• Sultan updated a variable.
• Ahmed closed the conversation.
• Conversation reopened automatically.
• Template was sent.
• Flow was triggered.

Display Requirements
• Show as system message (centered or styled differently from user messages).
• Light grey background or subtle system style.
• Smaller font.
• Include:
• Actor name
• Action description
• Timestamp

Example format:

Ahmed added tag: VIP
Sultan assigned this conversation to you
Manager removed assignment
Variable “Interested” updated by Sultan
Ahmed closed the conversation

These must be fetched from API or logged via backend events.

If backend does not provide these events:
→ API must be added to return conversation activity logs.

24. Display Customer Satisfaction Status in Chat Header

We require the satisfaction level to be displayed at the top of each conversation.

Location:
• In chat header, next to customer name.

Possible statuses:
• 😊 Satisfied
• 😐 Neutral
• 😠 Unsatisfied
• ⚪ No rating

Display:
• Emoji + text
• Clear visible badge next to customer name
• Must update dynamically if satisfaction changes.

Data source:
• Must come from backend (manual rating or AI-generated rating).

If no rating exists:
Display “No Rating”.

⸻

Important Implementation Notes
• System events must not be deletable.
• They must be part of conversation history.
• They must scroll normally with chat.
• They must not be mistaken for customer messages.
• Header satisfaction must refresh in real-time.
